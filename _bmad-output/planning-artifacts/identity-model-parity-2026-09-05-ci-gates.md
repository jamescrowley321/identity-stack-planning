## 2. Vacuous-pass analysis

**Changes filter** (ci.yml:46-68, dorny/paths-filter v4): `go: go/**`, `rust: rust/**`, `shared: spec/** | infra/** | .github/workflows/ci.yml`. The 5 native jobs run iff `go|rust|shared == 'true' || inputs.run-native-tests` (nightly.yml:43 forces the latter). `ci-complete` fails only on `failure`/`cancelled` results (ci.yml:651-656) — **skipped counts as pass by design** (ci.yml:44-45).

- **Python-only diff**: `integration-tests-go`, `go-checks`, `go-vulncheck`, `integration-tests-rust`, `rust-checks` all *skip* (path-filter skip → green via ci-complete). Intended.
- **Go/Rust-only diff**: every Python job **runs but proves nothing about the diff**. `ci / security-gate` is the documented worst case: mutation_security.py:665-669 prints "no security modules changed … no-op pass" in ~10-15s (issue #638's exact complaint). The only job applying real cross-language pressure on *every* PR is `spec-vector-coverage` (unconditional, runs all three runners).
- **Filter blind spots**: root `.env.node-oidc` / `.env.identityserver` provider profiles are sourced by the Go/Rust integration legs (ci.yml:394-396, 570-572) but are in **no filter** — a PR editing only those skips both native suites. Makefile is also not "shared" (harmless: CI native jobs inline their commands).
- **Fragility**: because the native jobs are required only via ci-complete's skipped-as-pass, a filter typo or directory rename would silently disable all Go/Rust gating with no red signal (mitigated: edits to ci.yml itself are `shared`).
- **security-gate on main pushes**: `BASE_REF` falls back to `main` (ci.yml:328-335) → empty diff → always no-op outside PRs. Fine (PR-time gate).

## 4. Release automation parity + the rust-v0.3.1 trigger

Chain (release.yml): push-to-main (paths-ignore `node/** spec/** infra/**`) → full reusable CI + OIDF conformance gate the core `release` job → serial version jobs `release → release-fastapi-version → release-go-version → release-rust-version`, each PSR 10.6.1 with a scope-routed parser (py/tools/release_parsers.py: Core drops `{fastapi,go,rust,node,spec,infra}` scopes; Go/Rust/fastapi keep *only* their own scope). Tags pushed via PAT trigger per-track publish workflows. Routing is **scope-based, not path-based**.

**rust-v0.3.1 verified — the "docs-only PR" observation is wrong in the details.** The docs PR (#640, bb4b0b7) landed *after* the release. rust-v0.3.1 (73b27de) was cut by the main-push of **PR #636** — an *unscoped* `ci:` squash commit. Mechanism: PSR 10's conventional parser parses **squash-commit bodies** by default (`parse_squash_commits`), and #636's squash body contains the inner bullet `* fix(rust): bump yanked wnaf 0.14.0 -> 0.14.1 to satisfy cargo-deny`. RustCommitParser kept that `(rust)`-scoped `fix` → patch bump → tag → crates.io publish. rust/CHANGELOG.md v0.3.1 confirms this. The scope routing worked as specified at parsed-commit granularity — and the wnaf bump was a genuine rust-track fix, so 0.3.1 is defensible — but the emergent rule is: **any squash-merged PR whose body contains a `fix(rust)|feat(go)|fix(fastapi)`-style bullet cuts a release of that track regardless of PR title/type.** Worth an explicit decision: document as intended, or disable squash-body parsing / strip bullets at merge time. `allowed_tags` includes `chore/ci/docs` in all four configs — changelog entries only, never bumps.
